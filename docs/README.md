# 文档索引

本目录存放本模组的开发文档。

面向玩家的使用说明见仓库根目录的 [README](../README.md)。

## 阅读顺序

初次接手时先读 [架构总览](architecture.md)，再读 [开发与构建](development.md)。
具体行为与数值以对应专题为详细说明入口，其他文档只保留摘要和链接。

## 书写规范

文档正文一句一行，使差异以句子为单位呈现，避免审阅时横向滚动。

- 一律使用书面语：表述须严肃，语法须规范。
  不得出现口语、白话、方言与网络用语，不得使用成分残缺的句子，也不得以语气词充当句尾。
- 一句一行：句子写完即换行。
- 每行不超过 120 列，与 `build.gradle` 里 palantir 的 `ColumnLimit` 一致。
  列宽按显示宽度算：中文与全角标点计 2 列，ASCII 计 1 列，所以一行大约只放得下 50~60 个汉字。
- 一行超宽时先改写：把拖着十几个分句的长句拆成几句，或拆成列表、表格，而不是在逗号处硬断。
- 改写以可读为先，不必与原文逐字一致，但类名、ID、数值与行为描述不得变。
- 段落之间空一行；列表项的续行按内容列对齐。
- 表格行不能换行：单元格只写结论，说明文字挪到表下的要点里。
- 代码块与命令行同样不强制换行。
- 换行只影响源码阅读，不影响渲染：Markdown 的单个换行在段落内会被合成为空格。

中文列宽与完整句子须人工审阅，不能仅依赖按空格断行的 Markdown 格式化工具。
